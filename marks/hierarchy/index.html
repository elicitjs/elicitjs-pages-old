Hierarchy

A hierarchy is nodes that sit inside each other, declared with structure: "hierarchy": one table of nodes, and a nesting table with one row per containment. Any mark that draws a node shape can be a container. A contains channel picks the rows that hold others, fit: true on a size channel sizes a container to its contents, and edit.hierarchy.nest drops a node into a container or out of one.

API reference

structure: "hierarchy"

Three tables: nodes, nesting and an optional links. One nesting row says one node is inside another.

schema: { structure: "hierarchy", tables: { nodes, nesting, links? } }
Options
OptionType · defaultDescription
nodes
tabledefaultrequired
One row per node. Needs a key: true column. Named anything with role: "nodes".
nesting
tabledefaultrequired
A field map like any other table, named anything with role: "nesting". Its first two ref columns are the contained node, then its container. A node has at most one container. Further columns take a type, domain and default as usual.
links
tabledefaultnone
As in a network: link() draws it and edit.network.* edits it.

channels.contains

A channel on the mark that draws the nodes. It says which rows can hold other nodes.

contains: true | { value | fn | field, padding }
Options
OptionType · defaultDescription
value | fn | field
boolean
value: true lets every row hold others. Use fn or field to decide per row.
padding
number | { top, right, bottom, left }default10
The room in px between a container’s edge and its contents. A fitted container is sized to leave it. A fixed one keeps its contents inside it.

channels.dodge

A channel on the mark that draws the nodes. Rows that take part are pushed clear of their siblings when a drag ends and when data is set from outside.

dodge: true | { value | fn | field, gap }
Options
OptionType · defaultDescription
value | fn | field
boolean
true is every row. Use fn or field to pick the rows that take part.
gap
numberdefault8
The space in px two siblings keep between them.

fit: true

A flag on a size channel. On a row that holds other nodes, the column is set from them.

width: { field, fit: true }
Options
OptionTypeDescription
channels
width | height | size | rx | ry | x1 | x2 | y1 | y2
The channel needs a field. The fitted value is written to it, so getData() reports the size that is drawn. The row’s x and y follow the centre of its contents.

edit.hierarchy.nest(options)

Drop a node into the container under the pointer, or out of one. Put it on the mark you drag, beside a move.

edit.hierarchy.nest({ defaults, when }) → Edit
Options
OptionType · defaultDescription
defaults
objectdefault{}
Values for any further columns of the nesting row it writes.

Declaring the structure

structure: "hierarchy" gives the dataset a nodes table and a nesting table. A links table is optional.

schema: {
  structure: "hierarchy",
  tables: {
    nodes: {
      id: { type: "categorical", key: true, open: true },
      kind: { type: "categorical", domain: ["group", "note"] },
      x: { type: "quantitative", domain: [0, 100] },
      y: { type: "quantitative", domain: [0, 100] },
      w: { type: "quantitative", domain: [0, 600] },
      h: { type: "quantitative", domain: [0, 400] },
    },
    nesting: {
      child: { type: "ref" },
      parent: { type: "ref" },
    },
  },
}

getData(), onChange and setData use one array per table. A table you leave out of data starts empty.

The nesting table

The nesting table is declared like any other table: a field map, with a type for every column.

It needs two ref columns. The first names the contained node and the second names its container. Both point at the nodes table's key: true column, so their values are node identities. The column names are yours.

nesting: {
  child: { type: "ref" },    // the contained node
  parent: { type: "ref" },   // its container
}

One row is one membership. A node with no row is at the top level. A node has at most one container, and cannot contain itself or any node inside it. A row from data or setData that breaks either rule is dropped with a warning, and so is a row that names a missing node.

Add any other columns you want to record about a membership. They take a type, a domain and a default like columns anywhere else. A row made by a drop takes each column's default, or the value you pass in edit.hierarchy.nest({ defaults }).

nesting: {
  child: { type: "ref" },
  parent: { type: "ref" },
  coder: { type: "categorical", domain: ["seed", "participant"], default: "participant" },
}

Deleting a node removes the nesting rows that name it. Its contents move to the top level.

Naming the tables

Name the tables for your data and give each a role: "nodes", "nesting" or "links". A table named after its role needs no role, which is the short form used above.

tables: {
  topics:      { role: "nodes",   fields: { … } },
  memberships: { role: "nesting", fields: { … } },
}

data, getData() and setData are then keyed topics and memberships. Marks and edits find each table by its role.

Named tables, and a column on the membership

Containers

A container is a row of an ordinary mark. Two channels set it up.

contains picks the rows that hold other nodes. { value: true } is every row. { fn } or { field } decides per row, so groups can hold notes while notes hold nothing.

fit: true on a size channel sizes the row to its contents. It applies to rows that hold other nodes. The channel names a field, and the fitted size is written to it.

rect({
  channels: {
    x: { field: "x" },
    y: { field: "y" },
    width: { field: "w", scale: null, fit: true },
    height: { field: "h", scale: null, fit: true },
    contains: { fn: (d) => d.kind === "group", padding: 12 },
  },
})

scale: null reads the column as pixels. padding is the room between a container's edge and its contents; see Padding and spacing.

A row with contents gets its fitted columns from them, so a resize edit leaves those columns alone. A row without contents keeps its own size and stays editable.

The fitted size is in the data, so other channels can read it. The examples here place a group's name from its h column.

Padding and spacing

Every container keeps padding between its edge and its contents. The default is 10px. Give one number, or a side each; a side you leave out takes the default.

contains: { fn: (d) => d.kind === "group", padding: { top: 30, right: 12, bottom: 12, left: 12 } }

A fitted container is sized to leave that room. A container with a size of its own moves its contents inside it.

dodge keeps nodes from overlapping. It is a channel like contains: true is every row, and { fn } or { field } picks the rows that take part. gap is the space they keep, 8px by default. Round nodes keep it edge to edge. A composite dodges as a whole, with every part, its label included.

dodge: { value: true, gap: 10 }

Nodes dodge their siblings: the contents of one container dodge each other, and so do the top-level nodes. When two overlap, the node you just dropped stays put and the other moves the shortest distance that clears it. When that leaves no room, the contents are packed in reading order from the top-left. A container that grows pushes its neighbours the same way, and they take their contents along. A pushed node stays inside its container's padding, or inside the plot at the top level. Where the space runs out, nodes spread as far apart as it allows.

Nodes are pushed apart on release, and when data arrives through setData. While you drag, they are drawn where the release will put them. Seeded data is spaced once, at the start. Without dodge, nodes stay where they are put.

Fixed containers

Leave fit off and a container keeps the size it was given. Use this for regions that are part of the question: buckets, lanes, zones. Lock them with lock so only the cards move. Cards stay inside the bucket's padding, and a locked row stays where it is when nodes dodge.

The answer is the nesting table: one row per card, naming its bucket.

Other shapes

Dragging in and out

Put edit.hierarchy.nest() on the mark you drag, beside move({ mode: "relative" }). The move carries the node. On release, the node joins the innermost container under the pointer. Released over no container, it leaves the one it was in.

While you drag, the chart shows what a release would do. The container the node would join is outlined and grows to hold it. The container it came from keeps its size while the pointer is inside it, and shrinks once the pointer leaves. With dodge, other nodes move out of the way, inside a container and at the top level. The data changes on release. Style the outline with the target state of effects.

A container stays where it is when you drag a node past it or out of it. Released against a container's edge, the node you dropped moves clear of it.

The layout eases to its new place. Nodes make room first and a container resizes after them. The node you drag stays on the pointer. Set the time with motion: { duration } on the spec, in milliseconds, or motion: false to draw each change at once. Motion is off when the reader's system asks for reduced motion.

The same move moves a container, and its contents travel with it.

A rule about which nodes may go where is a constraint on the nesting table. A drop the rule refuses shows no outline and leaves the data unchanged.

Add a links table and the nodes can be connected as in a network. link() draws the links and meets a container at its edge. A ports channel and edit.network.connect() work on the same mark.

Reading and setting from outside

Containment is stored as rows, so your code reads and writes it like any other data. getData() returns the nesting rows and each container's fitted size.

setData takes the same shape. Change the nesting rows and every container re-fits. A node sent with no x and y is placed inside the container it joins. With dodge, it is also moved clear of the nodes already there.

const data = chart.getData();
chart.setData({ ...data, nesting: [...data.nesting, { child: "n4", parent: "g2" }] });

// What a program (or a model) does: read the tables, write them back.
const button = (label, run) => {
  const b = document.createElement("button");
  b.textContent = label;
  b.style.cssText = "margin: 0 6px 8px 0; padding: 4px 10px; font: 12px system-ui; cursor: pointer;";
  b.onclick = run;
  return b;
};
const toolbar = document.createElement("div");
let minted = 0;
toolbar.append(
  // Re-parent by rewriting the nesting rows. No sizes or positions are sent.
  button("Move everything to Group B", () => {
    const data = el.getData();
    el.setData({
      ...data,
      nesting: data.nodes.filter((d) => d.kind === "note").map((d) => ({ child: d.id, parent: "g2" })),
    });
  }),
  // A new node with no x/y: it is placed inside the group it joins.
  button("Add a note to Group A", () => {
    const data = el.getData();
    const id = "new" + ++minted;
    el.setData({
      nodes: [...data.nodes, { id, label: "Added " + minted, kind: "note", x: null, y: null, w: 70, h: 26 }],
      nesting: [...data.nesting, { child: id, parent: "g1" }],
    });
  }),
  button("Ungroup all", () => el.setData({ ...el.getData(), nesting: [] })),
);
if (el.dom().parentNode) el.dom().parentNode.insertBefore(toolbar, el.dom());
