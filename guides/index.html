Guides

A guide draws the rule and the state: what a gesture is allowed to do, and what is left to do. It views the interface's state rather than rows, so it has no channels, no table and no edit, and writes no data. Declare one in guides: [...] (guides.rule, guides.region, guides.remaining, guides.proximity, guides.tip, guides.crosshair, guides.custom), or let an edit draw its own with guide:. Survey widgets use their own widget guides. Guides rebuild every render and let every gesture pass through. For hovered, selected and grabbed feedback, see Effects.

guides.tip(options) · tip (on a mark)

A tooltip of the row under the pointer. It reads state and writes nothing, so it never blocks a gesture, and it shows on read-only rows too. Every mark takes tip as a shorthand for a tip bound to that mark.

barY({ tip: true, … })                 // every column of the row
barY({ tip: ["city", "rain"], … })    // these columns
barY({ tip: (d) => `${d.city}: ${d.rain}`, … })

guide (on an edit)

Which kind you want

The two differ in who declares them.

guide: on an edit draws the edit's own rules. It already knows the channel, the scale and the constraints that gate it, so you repeat none of them. Use it to show what a gesture is allowed to do.

guides: [...] on the spec draws an annotation you choose — a target line, a shaded range — from whatever you compute out of the guide context.

Use the edit-owned form when the edit already knows what you want to draw. A guides.rule at a clamp limit restates that limit in a second place, and the two can drift apart.

An edit draws its own rules

guide: true on an edit turns on bounds and catchment. You repeat nothing from the constraints: the edit draws every dataset constraint whose field matches its own channel.

Bounds follow the edit's axis. The same clamp draws horizontal lines on a y-edit and vertical ones on an x-edit.

clamp and snap, drawn by the edit

guide: true draws the allowed band and a labelled line at each clamp limit.

const chart = Elicit({
  width: 400, height: 260,
  margins: { top: 16, right: 16, bottom: 28, left: 36 },
  data: [{ cat: "A", n: 55 }, { cat: "B", n: 30 }, { cat: "C", n: 70 }],
  schema: {
    cat: { type: "categorical", domain: ["A", "B", "C"] },
    n:   { type: "quantitative", domain: [0, 100] },
  },
  // The rules this chart enforces. An edit governed by them can draw them.
  constraints: [ clamp({ field: "n", min: 20, max: 85 }) ],
  marks: [
    bar({
      channels: {
        x: { field: "cat" },
        // `guide: true` turns on bounds and catchment. This edit has no proximity
        // pick, so only the bounds draw: the allowed band and a labelled line at
        // each `clamp` limit. You repeat none of it — the edit draws every
        // constraint whose `field` matches its channel.
        y: { field: "n", edit: move({ guide: true }) },
      },
    }),
  ],
});
mount(chart.dom());
Try: Drag a bar past a limit, or between the snap stops.

What is left to do

guides.remaining() states how much of a budget is still unallocated — the count a reader needs while placing tokens or splitting a total.

guides.remaining({ field: "y", unit: "token" })   // "3 tokens left"
guides.remaining({ field: "y", total: 100 })      // "45 of 100 left"

Pass no total and it reads the target from the chart's own maintainSum constraint, so the number you enforce and the number you show cannot drift apart. Set unit for the countable phrasing, anchor ("top-right" by default) for the corner, and label for a function of (remaining, used, total) when you want your own wording.

A budget with its remainder

guides.remaining reads the target from the maintainSum constraint, so the budget is written once.

const chart = Elicit({
  width: 380, height: 260,
  margins: { top: 26, right: 14, bottom: 26, left: 34 },
  // No `total` here: the guide reads the target off the maintainSum
  // constraint, so the budget is written once.
  guides: [ guides.remaining({ field: "y", unit: "point" }) ],
  data: [
    { x: "A", y: 25 }, { x: "B", y: 20 },
    { x: "C", y: 15 }, { x: "D", y: 10 },
  ],
  schema: {
    x: { type: "categorical", domain: ["A", "B", "C", "D"] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  constraints: [ clamp({ min: 0 }), maintainSum({ total: 100, strategy: "cap" }) ],
  marks: [
    barY({
      fill: "#8A78C0",
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move() },
      },
    }),
  ],
});
mount(chart.dom());
Try: Drag a bar — the count updates as the total moves.

Restyling the parts

guide: true is shorthand for the parts at their defaults. Pass an object to switch and restyle each one.

A snap's stops draw as short ticks at the plot edge, where the axis also sits. Raise bounds.tickLength and bounds.tickOpacity to pull them clear of it.

bounds draws the constraint boundaries: a clamp's band and limits, a snap's stops, a maintainSum cap. On with guide: true.

catchment draws the radius in which a proximity pick resolves a free pointer to a mark. On with guide: true. Edits that select a target (pick: "nearest", pick: "sweep", brushSpan, brushRect, edit.geo.brush) also turn catchment on when you omit guide. Set guide: false to turn it off.

track draws where a handle can travel, for handles whose range isn't a scale. Off by default — turn it on where that range isn't obvious from the mark, as on a face's parameters.

Each part takes color, dash, width and opacity; bounds adds bandOpacity, fontSize, tickLength and tickOpacity. A color on the guide itself sets all three parts at once. Theme tokens live at theme.guide.bounds|catchment|track (and theme.constraint.color).

One colour, or one per part

Left sets one colour for every part. Right styles each separately and lengthens the snap ticks.

// `guide: true` is shorthand for the parts at their defaults. Pass an object to
// switch and restyle each one.
const rows = [{ x: 30, y: 45 }, { x: 60, y: 62 }, { x: 84, y: 28 }];
const schema = {
  x: { type: "quantitative", domain: [0, 100] },
  y: { type: "quantitative", domain: [0, 100] },
};
const bounds = [
  clamp({ field: "y", min: 15, max: 80 }),
  snap({ field: "y", step: 10 }),
];

// One colour for every part.
mount(Elicit({
  width: 300, height: 220,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: rows, schema, constraints: bounds,
  marks: [
    point({
      size: 9,
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move({
          pick: "nearest", threshold: 40,
          guide: { bounds: true, catchment: true, color: "#1B3F60" },
        }) },
      },
    }),
  ],
}).dom());

// Or one per part. `snap` stops draw as short ticks at the plot edge, where the
// axis sits — `tickLength` and `tickOpacity` pull them clear of it.
mount(Elicit({
  width: 300, height: 220,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  data: rows, schema, constraints: bounds,
  marks: [
    point({
      size: 9,
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move({
          pick: "nearest", threshold: 40,
          guide: {
            bounds: {
              color: "#EE7B5E", dash: "6 2", width: 1.5, opacity: 1,
              tickLength: 18, tickOpacity: 0.9,
            },
            catchment: { color: "#94A5B3", dash: "1 4", width: 1, opacity: 0.35 },
          },
        }) },
      },
    }),
  ],
}).dom());

Rule and region

Annotations you declare in guides: [...]. guides.region shades a band, guides.rule draws a reference line. Both position in data space through the same scales a mark uses, so they stay put as points move.

A target band with a rule

guides.region shades 40–60; guides.rule marks the midpoint.

const chart = Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  guides: [
    guides.region({ y: [40, 60], fill: "#1B3F60", opacity: 0.14 }),
    guides.rule({ y: 50, label: "target 50" }),
  ],
  data: [{ x: 20, y: 30 }, { x: 50, y: 55 }, { x: 80, y: 70 }],
  schema: {
    x: { type: "quantitative", domain: [0, 100] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  marks: [
    point({
      fill: "#1B3F60",
      size: 9,
      channels: {
        x: { field: "x" },
        y: { field: "y" },
      },
      edits: [ move({ channels: ["x", "y"] }) ],
    }),
  ],
});
mount(chart.dom());
Try: Drag a dot in and out of the target band.

Guides derived from the data

Every option takes a literal or a function of the guide context ({ data, scales, features, ui, width, height, stage }), so an annotation can read the rows it annotates. Here one rule is a fixed target and the other is the running mean. Guides rebuild each render, so it recomputes on every commit. The band tracks the spread the same way.

A mean line that chases the bars

guides.rule({ y: ({ data }) => d3.mean(data, (d) => d.y) }) reads the dataset.

const chart = Elicit({
  width: 380, height: 260,
  margins: { top: 14, right: 14, bottom: 26, left: 30 },
  guides: [
    // A literal: a fixed reference.
    guides.rule({ y: 50, label: "target 50" }),
    // A function of the context: recomputed from the live rows every render.
    guides.region({
      y: ({ data }) => [d3.min(data, (d) => d.y), d3.max(data, (d) => d.y)],
      fill: "#50AEB7", opacity: 0.10,
    }),
    guides.rule({
      y: ({ data }) => d3.mean(data, (d) => d.y),
      label: "mean",
      stroke: "#EE7B5E",
    }),
  ],
  schema: {
    x: { type: "categorical",  domain: ["A", "B", "C", "D"] },
    y: { type: "quantitative", domain: [0, 100] },
  },
  data: [
    { x: "A", y: 30 }, { x: "B", y: 55 },
    { x: "C", y: 45 }, { x: "D", y: 70 },
  ],
  constraints: [ clamp({ field: "y", min: 0, max: 100 }) ],
  marks: [
    bar({
      fill: "#50AEB7",
      channels: {
        x: { field: "x" },
        y: { field: "y", edit: move() },
      },
    }),
  ],
});
mount(chart.dom());
Try: Drag a bar. The fixed target holds; the mean line and the band follow.

Tooltips

tip: true on any mark shows a tooltip of the row under the pointer: one column: value line per column. Pass a list of columns (tip: ["city", "rain"]) to show only those, or a function of the row (tip: (d) => string) for your own wording.

A tip is a guide, so gestures pass through it: drag a bar while its tooltip is showing. It also shows on read-only rows, such as a locked seed or a context row.

guides.tip() is the long form. text takes the columns or a function of the row returning a string or an array of lines. anchor: "mark" pins the box beside the mark's centre instead of the pointer, and mark limits it to the mark with that id. format sets how numbers print, as a d3 format specifier or a function.

A tip on every bar

tip: true on a barY with move(). The tooltip follows the pointer; the drag works underneath.

const chart = Elicit({
  width: 400, height: 260,
  margins: { top: 16, right: 16, bottom: 32, left: 40 },
  schema: {
    city: { type: "categorical", domain: ["Lima", "Oslo", "Pune", "Rome"] },
    rain: { type: "quantitative", domain: [0, 100] },
  },
  data: [
    { city: "Lima", rain: 12 }, { city: "Oslo", rain: 64 },
    { city: "Pune", rain: 78 }, { city: "Rome", rain: 41 },
  ],
  marks: [
    barY({
      fill: "#50AEB7",
      // A tooltip of the row's columns. The bars stay draggable under it.
      tip: true,
      channels: {
        x: { field: "city" },
        y: { field: "rain", edit: move() },
      },
    }),
  ],
});
mount(chart.dom());
Try: Hover a bar to read it · drag it while the tip is showing.

A tip in your own words

guides.tip({ anchor: "mark", text: (d) => [...] }) writes two lines beside the point.

const chart = Elicit({
  width: 400, height: 260,
  margins: { top: 16, right: 16, bottom: 32, left: 40 },
  schema: {
    party: { type: "categorical", domain: ["Green", "Labour", "Liberal", "Other"] },
    share: { type: "quantitative", domain: [0, 60] },
  },
  data: [
    { party: "Green", share: 12 }, { party: "Labour", share: 38 },
    { party: "Liberal", share: 31 }, { party: "Other", share: 9 },
  ],
  guides: [
    guides.tip({
      anchor: "mark",
      text: (d) => [`${d.party}`, `${d.share.toFixed(0)}% of the vote`],
    }),
  ],
  marks: [
    point({
      fill: "#7DB86B", size: 8,
      channels: {
        x: { field: "party" },
        y: { field: "share", edit: move() },
      },
    }),
  ],
});
mount(chart.dom());

Crosshair

guides.crosshair() draws dashed rules through the pointer across the plot. Each rule reads the value under the pointer off its axis, at the plot's bottom and left edges. Set x: false or y: false to draw one rule, and readout: false to drop the labels. format sets how the readouts print.

The rules hide when the pointer leaves the plot. Gestures pass through them.

A crosshair with readouts

guides.crosshair({ format: ".1f" }) reads hours and score under the pointer.

const chart = Elicit({
  width: 420, height: 260,
  margins: { top: 16, right: 16, bottom: 32, left: 40 },
  schema: {
    hours: { type: "quantitative", domain: [0, 12] },
    score: { type: "quantitative", domain: [0, 100] },
  },
  data: [
    { hours: 2, score: 35 }, { hours: 4, score: 52 },
    { hours: 7, score: 68 }, { hours: 10, score: 81 },
  ],
  guides: [guides.crosshair({ format: ".1f" })],
  marks: [
    point({
      fill: "#EE7B5E", size: 6,
      channels: { x: { field: "hours" }, y: { field: "score" } },
      edits: [move({ channels: ["x", "y"] })],
    }),
  ],
});
mount(chart.dom());
Try: Move over the plot to read both axes · drag a point to an exact value.

Widget guides

The widgets draw their chrome with guides you can also use in your own spec:

  • guides.prompt(text, { y }) draws the question in the top margin.
  • guides.optionRings({ labelOffset, radius }) draws a Likert scale's rings and labels.
  • guides.cellGrid({ pad }) draws a matrix's cells and headers.
  • guides.sliderTrack({ format }) draws a slider's track with end labels.
  • guides.quadrants({ x, y }) draws centred axes with a label at each end.

Each reads its colours from theme.widget.
