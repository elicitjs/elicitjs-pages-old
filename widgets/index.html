Widgets

Widgets are ready-made elicitation interfaces for survey questions. Each one returns an ElicitSpec built from ordinary marks, edits and constraints, with its chrome drawn as guides. Render one with Elicit(widgets.likert({…})). A design sets how all thirteen are drawn, and you choose one with theme. The Likert scale below appears both as a widget and as the plain-API spec it expands to.

API reference

widgets.likert · multipleChoice · slider · matrix · lineCone · ranking · allocation · …

Import from elicit.widgets. Each returns an ElicitSpec; pass it straight to Elicit. The chart draws one dataset, so getData() reads the answer.

Returns / emits

An ElicitSpec — an ordinary spec, so you can read it, change one key, and pass it on. The chrome each widget draws itself with is a guide: guides.prompt, guides.options, guides.cellGrid, guides.sliderTrack, guides.quadrants. The plain-API twins below use those same guides, so each block stands alone.

Likert scale — widget & plain API

A point on a band of options, a create({ pick: "probe" }) edit, and count({ max: 1, strategy: "replace" }). Hover to preview the answer, and click to set it. The plain-API version uses the same mark, edit and constraint, and draws the same look with inline guides.custom helpers.

As a widget

Rings, track and labels come from the guide layer.

const chart = Elicit(widgets.likert({
  question: "This tool is easy to use",
  options: ["Strongly disagree","Disagree","Neutral","Agree","Strongly agree"],
}));
mount(chart.dom());
Try: hover across the scale, then click.

The same thing, plain API

Same mark, edit, and constraint — rings/prompt defined inline as guides. This is what widgets.likert expands to.

const options = ["Strongly disagree","Disagree","Neutral","Agree","Strongly agree"];
const radius = 11;

const prompt = (text) => guides.custom(() => [{
  type: "text", x: 0, y: -18, text,
  textAnchor: "start", fontSize: 13, fill: "#20555A",
}]);

const rings = () => guides.custom((ctx) => {
  const cats = ctx.scales.x.domainConfig || [];
  const cy = ctx.height / 2;
  const cxOf = (c) => ctx.scales.x.encode(c);
  const nodes = [];
  for (let i = 0; i < cats.length - 1; i++) {
    nodes.push({
      type: "line",
      x1: cxOf(cats[i]) + radius, y1: cy,
      x2: cxOf(cats[i + 1]) - radius, y2: cy,
      stroke: "#D9E2E9", strokeWidth: 3, background: true,
    });
  }
  for (const c of cats) {
    nodes.push({
      type: "circle", cx: cxOf(c), cy, r: radius,
      fill: "none", stroke: "#BCC9D4", strokeWidth: 1.5,
    });
    nodes.push({
      type: "text", x: cxOf(c), y: cy + 30, text: String(c),
      textAnchor: "middle", fontSize: 12, fill: "#20555A",
    });
  }
  return nodes;
});

const chart = Elicit({
  width: 560, height: 130,
  margins: { top: 34, right: 60, bottom: 44, left: 60 },
  axes: false,
  data: [],
  schema: { choice: { type: "ordinal", domain: options } },
  scales: { x: { type: "band" } },
  constraints: [ count({ max: 1, strategy: "replace" }) ],
  guides: [ prompt("This tool is easy to use"), rings() ],
  marks: [
    point({
      id: "likert",
      size: radius - 3,
      fill: "#50AEB7",
      channels: { x: { field: "choice" } },
      edits: [ create({ pick: "probe", channels: ["x"], advance: false }) ],
    }),
  ],
});
mount(chart.dom());
Try: same look, same interaction — change any line to customize.

Line + Cone

A two-step correlation question. Aim the line and click, then open the cone and click. getData() returns [{ r, spread }], and on("stage") reports which question you are on (2 = both answered).

It is a preset over trendBand and trend on one dataset. A pinned intercept: { datum: 0 } channel and two clamp constraints state the correlation. The trend page has the same spec written out. The inner plot is square, so the line’s screen angle reads as r.

Line + Cone

Crosshair frame and high/low variable labels are guides.

Ranking

Each item is a card. Drag one to reorder the list: rank() on the card's body writes the new order as you cross each slot, and the other cards shift by one place. The card follows the pointer, the others ease into their slots, and the card eases into its own when you let go. With reduced motion on, cards step from slot to slot.

The card is a composite: a rect body that carries the rank() edit, with the rank and the label drawn on it. motion: true on the glyph eases its parts when the order changes. Along the rank channel, whose scale is a band of slots, it draws the grabbed card at the pointer. motion: true works on any mark, and spec.motion sets the duration.

Ranking

A card per item. The whole card is the handle.

  items: ["Cost", "Speed", "Quality", "Risk"],

Try: Drag a card up or down. The others make room.

The same thing, plain API

A composite card, rank() on its body, and motion: true.

// What widgets.ranking expands to: one card per row, a rank edit on its body,
// and motion: true on the glyph.
const items = ["Cost", "Speed", "Quality", "Risk"];
const chart = Elicit({
  width: 420,
  height: 238,
  margins: { top: 34, right: 16, bottom: 4, left: 16 },
  axes: false,
  schema: {
    item: { type: "categorical", domain: items },
    rank: { type: "ordinal", domain: [1, 2, 3, 4] },
  },
  // The band runs down the plot, so rank 1 is at the top.
  scales: { y: { type: "band", padding: 0.17, range: [0, 200] } },
  data: items.map((item, i) => ({ item, rank: i + 1 })),
  effects: {
    hovered: { outline: false, stroke: "#94a3b8" },
    grabbed: {
      stroke: "#2563eb",
      strokeWidth: 1.5,
      cursor: "grabbing",
      filter: "drop-shadow(0 6px 9px rgba(15, 23, 42, 0.18))",
    },
  },
  marks: [
    composite({
      id: "card",
      motion: true,
      channels: {},
      parts: [
        // The body spans the plot and takes the drag.
        rect({
          height: 40, rx: 10, fill: "#ffffff", stroke: "#d5dbe5",
          channels: { y: { field: "rank", edit: rank({ cursor: "grab" }) } },
        }),
        // The rank and the label are inert, so a press on them reaches the body.
        text({
          fill: "#2563eb", fontWeight: 600,
          channels: { x: { value: 20 }, y: { field: "rank" }, text: { field: "rank" } },
        }),
        text({
          fill: "#0f172a", fontSize: 13,
          channels: {
            x: { value: 40 }, y: { field: "rank" },
            text: { field: "item" }, textAnchor: { value: "start" },
          },
        }),
      ],
    }),
  ],
});
mount(chart.dom());
Try: Drag a card by its label. The press reaches the body.

Designs

A design sets how every widget is drawn: its options, the answer inside them, a slider's track, a ranking card, a bar. Four ship with the library. ring is the default and draws rings on a track. The other three come with a named theme.

  • The default theme draws ring: rings on a track, and the answer is a filled dot.
  • theme: "survey" draws box: each option is an outlined box holding a radio or a checkbox.
  • theme: "surveyBlocks" draws block: options are soft blocks, and the chosen one turns solid.
  • theme: "surveyLines" draws line: controls and hairlines, with nothing boxed.

Pass the theme to a widget, or call setTheme("survey") once to draw every widget that way. The three form designs stack multiple choice as a list. The gestures, the data and the constraints are the same in every design.

Customizing styles

Every widget accepts a theme, which restyles the answer ink, chrome and affordances together. See Theming. The widget tokens live in theme.widget: design names the design, and the rest are the colours and sizes it reads. Start from a named theme with extends and change the tokens you need.

The design and the colours are separate tokens, so any theme takes any design: theme: { extends: "dark", widget: { design: "block" } } draws blocks in the dark theme's colours.

For a one-off change to a single widget, edit the plain-API version: repaint the answer mark or swap a guide. The edits and constraints stay the same.

    extends: "survey",

Add a design

authoring.registerDesign(name, design) adds a design. A design is an object of drawers, one per part. Each drawer takes the box to draw in and the widget tokens, and returns scene nodes in plot pixels. State the parts you change and name the design to start from in extends. Every widget then draws with it.

A design may state these parts:

  • option(o, t) draws one option. o is its box (x, y, width, height, cx, cy) with label, selected, control ("radio" or "check") and layout ("row", "list" or "cell" for a matrix).
  • answer(o, t) describes the answer's ink: { shape: "dot" | "square" | "block", size, corner, left, top }. A block fills the option. left and top place a dot or a square on the control.
  • grid(g, t) draws chrome around a whole matrix, and slots(l, t) the lines between a ranking list's slots.
  • track(s, t) draws a slider's track from x1, x2, y and at (the value's pixel). thumb(t) describes its handle.
  • card(c, t) lists a ranking card's parts, back to front: body, badge, rank, label and grip. Place each with left or right, measured from the card's edge. The body takes the drag, and its hovered and grabbed styles become the chart's effects.
  • bar(t) describes a bar in the widgets drawn on chart axes: { corner, fillOpacity, track }.
  • list stacks multiple choice as a list. tiles sizes the plot to the options from optionHeight, rowHeight and gap.
  • theme registers a named theme with the design, so theme: "pill" selects both.

Take colours and sizes from the tokens t, so a theme can change them. authoring.labelNode, authoring.checkNode and authoring.controlNodes draw the label, the tick and the empty control the built-in designs share. A design holds functions, so register it in JavaScript. A JSON spec then names it like any other: "theme": "pill".

A pill design

Two drawers and a theme, extending box.

// A design states the parts it changes. The rest come from the design it extends.
authoring.registerDesign("pill", {
  extends: "box",
  // One option: a pill with its label inside.
  option: (o, t) => [
    { type: "rect", x: o.x, y: o.y, width: o.width, height: o.height,
      rx: o.height / 2, fill: t.surface,
      stroke: o.selected ? t.accent : t.stroke, strokeWidth: 1 },
    authoring.labelNode(o.label, o.cx, o.cy, t, {
      width: o.width - 12,
      fill: o.selected ? t.onAccent : t.label,
    }),
  ],
  // The answer's ink: a block that fills the chosen pill, under its label.
  answer: (o, t) => ({ shape: "block", corner: o.height / 2 }),
  // Registers theme: "pill" with the design's own tokens.
  theme: {
    extends: "survey",
    widget: { accent: "#0f766e", optionHeight: 40, gap: 6 },
  },
});

  value: "Often",

More instruments

Allocation, tokens, intervals, histograms, regions, thermometers and labelled values. Each accepts question, onChange, stage and theme. Starting answers use options specific to each widget, such as value, values, bins or mean / lo / hi.

interval is three move() handles over one row, coupled by constraints. follow carries the caps with the mean, ordering keeps lo ≤ mean ≤ hi, and clamp holds all three inside domain. symmetric: true adds symmetric, so dragging one cap mirrors the other about the mean.
